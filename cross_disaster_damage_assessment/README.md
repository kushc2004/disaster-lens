# Cross-Disaster Building Damage Assessment

This folder defines the focused CV version of DisasterLens for a CV, final-year project, or research portfolio:

> Can a building-damage model trained on some disasters generalize to unseen disaster events, locations, and—when the audited metadata permits—unseen disaster types?

The implementation intentionally reuses the tested `src/disasterlens` package rather than duplicating the existing M0–M2 pipeline. The root project already supplies the BRIGHT audit, manifests, label validation, event-safe splits, synchronized transforms, early-fusion U-Net, training engine, losses, and evaluators.

This focused version has three deliverables:

1. A reproducible cross-disaster benchmark using the existing event-held-out split infrastructure.
2. A comparison between the existing U-Net and pseudo-Siamese ResNet-18 baseline; a ChangeFormer-style model is a separately tracked extension, not an unverified claim.
3. Calibration and uncertainty analysis for the best held-out model.

## Scope boundary

- **In scope:** paired pre-event optical and post-event SAR BRIGHT inputs, building-damage segmentation, event-level generalization, model comparison, and calibration.
- **Out of scope for this variant:** WorldPop/OSM context, priority ranking, Monte Carlo response allocation, and the Streamlit decision-support application.
- **Data boundary:** use only official BRIGHT data configured through `DISASTERLENS_BRIGHT_ROOT`. Do not fabricate inputs, labels, events, or metrics.

## Status

The shared M0–M2 implementation has a passing local test suite (`19 passed` on 2026-08-21). A passing test suite validates code behavior; it does not establish model quality or cross-disaster results. Those claims require saved training and evaluation artifacts.

Read [IMPLEMENTATION_SPEC.md](IMPLEMENTATION_SPEC.md) before extending the shared code.

## Run the focused benchmark

All generated artifacts are isolated under `outputs/cross_disaster_damage_assessment/`; root M0--M2 artifacts are read but never replaced. The runner requires the existing official M1 manifest and `DISASTERLENS_BRIGHT_ROOT`.

```bash
# First, audit the existing official manifest and create immutable splits.
python cross_disaster_damage_assessment/run.py prepare

# E1 and E2 on the same standard split, then evaluate both partitions.
python cross_disaster_damage_assessment/run.py train --model unet --split outputs/cross_disaster_damage_assessment/splits/standard.json --epochs 30
python cross_disaster_damage_assessment/run.py evaluate --run-dir outputs/cross_disaster_damage_assessment/runs/unet/standard --partition val
python cross_disaster_damage_assessment/run.py evaluate --run-dir outputs/cross_disaster_damage_assessment/runs/unet/standard --partition test

python cross_disaster_damage_assessment/run.py train --model siamese_resnet18 --split outputs/cross_disaster_damage_assessment/splits/standard.json --epochs 30
python cross_disaster_damage_assessment/run.py evaluate --run-dir outputs/cross_disaster_damage_assessment/runs/siamese_resnet18/standard --partition val
python cross_disaster_damage_assessment/run.py evaluate --run-dir outputs/cross_disaster_damage_assessment/runs/siamese_resnet18/standard --partition test
```

For each event generated by `prepare`, repeat the same paired commands with `splits/event_holdout/<event>.json`. Then calibrate either completed model run only after both its validation and test predictions exist:

```bash
python cross_disaster_damage_assessment/run.py calibrate --run-dir outputs/cross_disaster_damage_assessment/runs/siamese_resnet18/<event>
python cross_disaster_damage_assessment/run.py report
```

`calibrate` fits the scalar temperature from validation prediction bundles only; held-out labels are read only for post-fit metrics. The audit writes `disaster_types.csv` with leave-one-type-out eligibility, but does not run a type-held-out benchmark automatically.

### Kaggle T4

Attach the official `bright-dataset` Kaggle input, push the public repository, and run the existing Kaggle bootstrap cell in `notebooks/train.ipynb`. It detects Kaggle's nested upload layout, normalizes it when necessary, and sets `DISASTERLENS_BRIGHT_ROOT` (normally to `/kaggle/working/bright-normalized`). Then run the focused commands from the repository root:

```python
import os
from pathlib import Path
assert Path(os.environ["DISASTERLENS_BRIGHT_ROOT"]).is_dir()
!python -u cross_disaster_damage_assessment/run.py prepare
```

The runner prints each delegated training command and the shared trainer prints epoch and batch progress. Kaggle captures `outputs/cross_disaster_damage_assessment/` as the only focused-project output tree.
